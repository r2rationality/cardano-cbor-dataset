certificates is nonempty_oset<certificate>, and OSet decodes an empty one without complaint: the ledger does not check emptiness in the type. It checks it at the one transaction body field that carries certificates, key 4, with

    bodyFields 4 = fieldGuarded (emptyFailure "Certificates" "non-empty") ...

so a transaction body carrying an empty one is refused and the standalone bytes are not. certificates is referenced nowhere else in the Conway specification, so the constraint is enforced everywhere it can be reached.
